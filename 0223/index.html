Что упрощено в представлении

  • Статусы читаются цветом и текстом одновременно — бейджи с точкой-индикатором (pulse для «Tasdiqlanmoqda»). Долг и pending-оплата видны на первом же скролле.
  • Визит = сессия с таймером. «Сначала начните визит» — единый лок-состояние вместо серой массы заблокированных кнопок.
  • Одна нижняя CTA-панель на карточке клиента: до визита «Начать визит», в сессии — таймер + «Завершить» + «Добавить оплату». Действия по статусам не выпадают за пределы видимости.
  • Три уровня деталей оплаты: карточка-счётчик на Главной → sheet «Оплаты» → полная страница «Информация оплаты». Один и тот же поток из bell-уведомления и из меню.
  • Синхронизация вынесена в явный сценарий с шагами, прогрессом и повтором; офлайн-пилюля объясняет, что изменения хранятся локально.
  • «Остаток в машине» — это инвентарь кузова (наименования, остаток vs загружено), не список доставок. Название, иконка грузовика и подпись накладной это подчёркивают.
  • Конфиг-зависимые элементы не прячутся молча: вместо пропавшего пункта показывается объяснение на UZ («…admin panelda o'chirilgan»).
  • Форма «ARIZA YUBORISH» — тёмная кнопка, отделённая от обычных CTA: отправка заявки ≠ подтверждение платежа. Подпись связывает с web-разделом «Заявки на оплату экспедиторов».

Что сохранено без изменений

  • Все 4 таба, весь состав drawer (включая «Поделиться» со «Скоро!» и «Добавить аккаунт»), версия в футере меню.
  • Все статус-словари (заказ UZ, оплата UZ, накладные RU, причины UZ/RU) и способы оплаты Naqd/Карта/Terminal/Pereches.
  • Все бизнес-правила: оплата завершается только после подтверждения кассы; «Bekor qilindi» экспедитору не меняется; возврат с полки, бонусы, акт сверки, баланс по агентам, незавершённые заказы — на месте.

  • Легаси-экран заказа (deep link) с 5 действиями — сохранён как отдельный экран.

Потоки в 2–3 касания

  • Начать визит: Визиты (таб) → карточка → «Начать визит». Итого 3 касания.
  • Доставить: внутри визита → «Доставлено» (с отпечатком) → подтверждение → оплата в той же панели.
  • Собрать долг: Должники → карточка → «Оплата» → сумма → «ARIZA YUBORISH» → статус «Tasdiqlanmoqda».
  • Статусы первого взгляда: цвет точки + текст; долг — красная карточка слева; pending — amber pulse; ошибка синхронизации — красный баннер с повтором.

Состояния

Empty
«Пока здесь пусто» (отчёты, sheets, акт сверки, история, возвраты), «Незавершённых заказов нет», «В машине нет товаров», «Нет новых уведомлений»
Loading
Сплэш, bootstrap, синхронизация по шагам, «Определяем геолокацию…», «Начинаем…», скелетоны
Error
«Ошибка: …» карточки с повтором; синхронизация — шаг с ошибкой; возврат — «Qayta urinish»; код RETURN_DISABLED → человеческий RU текст
Offline
Пилюля «Нет соединения · изменения сохраняются локально», отложенные заявки отправляются при восстановлении

Критерии успеха

  • Водитель начинает визит в 2–3 касания с любого места (активный таб, маршрут, должник, незавершённый заказ).
  • Статус заказа, размер долга и pending-оплата читаются без нажатий — цвет, бейдж, число.
  • Выключенные конфиги не ломают навигацию: вместо пустоты — объяснение на UZ.
  • Синхронизация и подтверждение кассы — два отдельных, явных состояния.
